9. 2 · The Agent Behaviour Policy · Four barriers, and only one is a control · 1:30 · in the 20-minute version

What stands in the way of each row

nonenothing in the waya token and no instructionsnot a control
expectationa rule in prose, kept by nobody but the agenta line in CLAUDE.md or ChatGPT's instructionsnot a control
settinga switch the agent's own account could flipa hook, an approval promptnot a control
boundaryenforced above the grant, out of the agent's reacha token scope, branch protection, a sandbox, the kernela control

A control bounds a grant only if it is enforced by something the grant does not include.

Cue. Step down the ladder; the enforcer test comes last.

For every row, what actually stands in the way is one of four things. Nothing. An expectation: a rule in prose that the agent follows if it chooses to. A setting: a switch the agent's own account could flip. Or a boundary: enforced by something the grant does not include. Only a boundary is a control. For most deployments today, the honest answer is the second row.

15. 5 · Process Behaviour Policies: SHarness · An ABP describes. A PBP executes. · 1:30 · in the 20-minute version

Process Behaviour Policies · SHarness, the secure harness

An ABP describes an agent's behaviour. A PBP is that description executed, underneath the agent.

{"pbp": 1, "id": "p0-hello-world",
 "files":   {"read":  ["/usr", "/lib", "/bin", "/etc", "/work"],
             "write": [],
             "exec":  ["/usr", "/lib", "/bin"]},
 "network": "none",
 "process": {"no_new_privs": true,
             "max_memory_mb": 64, "max_pids": 8}}
  1. The text: a small canonical JSON, what the process may read, write, run and connect to.
  2. The hash, from outside: sha256:a6244d34…, supplied by the person. A tricked agent cannot widen what it cannot rename.
  3. An enforcer it does not include: the Linux kernel (Landlock), told before the process starts.

Open source · Python standard library only · pip install sharness-ai · Linux 5.13 or later

Cue. Step: the PBP text, its hash, the three things that make it binding.

This is what is new since the last time many of you saw us. A Process Behaviour Policy is the Agent Behaviour Policy applied to one process: what that process may read, write, run and connect to, as a small piece of JSON, hashed to one name. The person supplies the hash from outside, and the Linux kernel enforces it before the process starts. A tricked agent cannot widen it, because the kernel was told first. SHarness is the open-source enforcer, secure harness.

19. 5 · Process Behaviour Policies: SHarness · What SHarness can and cannot stop today · 1:15 · in the 20-minute version

A tampered Claude Code extension, 29 October: what a written policy refuses

Adds an SSH key to ~/.ssh/authorized_keysa write outside the workspacerefused today
Plants persistencea write outside the workspace; a writable path is never executablerefused today
Opens a reverse tunnelno network, or only the hosts you namedrefused today
Reads the names of your secretskeys held by a door, never handed overdesigned
Runs inside the editor on loada boundary around the editor itselfdesigned

Would SHarness have stopped it? No, not today: Linux only, and nothing yet confines an editor. Every step it took is one a written policy refuses.

Cue. Step down the table; land on 'no, not today'.

The honest column. Last week a tampered Claude Code extension was served for about eleven hours: it added an SSH key, planted persistence and opened a tunnel. A written policy refuses every one of those steps, and three of those refusals run today on Linux. But the build targeted macOS and Windows, and nothing yet confines an editor. So the honest answer is no, not today. Every step it took is one a written policy refuses, which is the argument for having one.
